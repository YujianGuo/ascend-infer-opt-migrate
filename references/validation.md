# 目标端验证与交付

编译、功能、收益分别给出结论。复用项目已有测试与 benchmark，只有缺少必要验证能力时才补最小测试/采集脚本。

## 可比性与精度

记源端 baseline/candidate 为 S0/S1，目标端 baseline/candidate 为 T0/T1。S0/S1 解释源收益；T0/T1 判定迁移是否保留优化价值。跨硬件、跨模型或跨 vLLM-Ascend 版本的 S1/T1 差异包含设备、模型或框架变化，不能直接声称迁移优化收益。

版本迁移的 T0/T1 固定目标 vLLM-Ascend/vLLM commit 及配套依赖，仅引入待验收迁移改动；记录目标已内置优化的启用状态。已内置且无法独立关闭时说明收益不可单独归因，不能叠加重复实现或引用旧版本结果代替目标验收。按 [版本迁移指南](vllm-ascend-version.md)核对接口、加载路径、构建产物与恢复边界。

目标对照固定模型/权重 revision、tokenizer/processor、软件、硬件、拓扑、精度/量化、采样、真实输入输出 token 数、并发、并行与图模式。若用户迁移的优化本身改变并行/调度参数，记录变化为被测变量，并增加用于归因的对照。不同模型的 tokenizer 不同，记录目标实际 token 长度，不能按相同文本假设相同负载。

测试根据受影响契约安排：

| 层次 | 检查 |
|---|---|
| 仓库 | 项目要求的格式、静态检查、受影响单测/集成测试；检查真实 diff |
| 算子 | 真实目标 dispatch、目标 dtype/shape、尾块、stride/device/索引边界、标准参考与容差 |
| 模型 | Prefill logits、多个 Decode step、KV/循环状态、目标任务精度；确定性设置下 token/hash 对照 |
| 图 | 用户要求的 eager、capture、replay；动态长度/batch、非预期重编译、旧缓存和元数据刷新 |
| 服务 | ready/health、流式响应、混合请求、取消/超时、资源释放；并行检查全 ranks |
| PD | 完整请求从 P 到 D、KV/元数据接收与消费、首步/后续 decode 精度、断链/重复交接与回收 |

回退测试验证“不满足能力/shape 时仍正确”，优化测试验证“满足时确实调用优化路径”，两者结果分开。项目精度标准和验收输入应在实验前固定；不得通过跳过失败用例或放宽容差换取通过。

非确定模型（MoE 路由、投机解码、bf16 归约）先用**同一配置重复采样**测出模型噪声底，
再判断跨配置差异；差异小于噪声底时不得判为精度回归，也不得用单次贪心文本差异下结论。
算子级用目标 dtype 对应的 fp32 参考实现比对，误差应落在该 dtype 舍入量级。

## 路径归因证据

缺少“优化实际被调用”的证据时，功能跑通只能说明兼容。归因优先选择运行时可见的手段：

1. 显式 debug 开关 + WARNING 级一次性日志，打印真实 shape/dtype/分支；
2. dispatch / 调用计数；
3. profiler 中的算子名与耗时。

先做可见性预检：日志级别在模型执行期可能被过滤；`torch.compile` 追踪范围内不能用 `print`（会打断编译）。
日志应放在不被追踪的自定义 op / 分支内。只凭“代码里写了分支”不作为命中证据。
详见 [踩坑与排查清单](pitfalls.md) A、G 节。

## 实验设计与噪声底

基准负载必须与优化目标匹配，否则效应会被无关阶段淹没：

| 优化目标 | 隔离负载建议 | 主指标 |
|---|---|---|
| Prefill | 长输入 + 输出 1 token + 并发 1（TTFT 由 prefill 主导） | TTFT mean/median/p99、输入 tokens/s |
| Decode | 固定 batch/长度，稳定步数 | TPOT、ITL、输出 tokens/s |
| 整体 | 线上混合负载 | 请求吞吐、SLO 内吞吐、排队 |

最低样本设计：**每个配置 ≥2 个独立服务会话 × 每会话 ≥3 次重复**。会话间差异估计漂移，
重复间差异估计测量噪声；效应量大于会话漂移才可下结论，否则报告“噪声内/证据不足”，
不挑选最快样本。会话切换只改被测开关，启动脚本其余部分保持一致。

## 性能与内存

服务 readiness 完成后预热至稳态，剔除模型加载/编译；记录预热、样本数量、采集时段、随机种子和排除规则。NPU 微基准使用项目设备同步/事件计时或 profiler，不能只测 Python 异步提交耗时。Profiler 采集与不带 profiler 的 E2E 基准分开，保留原始日志/CSV/trace。

交替运行 T0/T1 的配对会话或项目已有的等效控制实验，检查相邻 baseline 漂移与异常。根据实际负载选择重复量；效果落在噪声内时增加样本或报告证据不足，不靠单次最快样本给结论。

| 类别 | 记录及口径 |
|---|---|
| Prefill | TTFT 的 mean/median/p95，若可拆则列排队/Prefill；输入 tokens/s |
| Decode | 请求级 TPOT 的 mean/median/p95；实际输出 tokens/s；ITL 若可采集则单独列，不能混称 TPOT |
| 整体/调度 | E2E latency、成功请求数、错误率、SLO 内请求吞吐、排队/抢占；公平性按项目标准 |
| 内存 | 设备实际峰值与稳态、allocator allocated/reserved（可取时）、KV/workspace/graph pool；不可将 reserved 等同全部显存 |
| PD/通信 | KV 字节量、交接/传输/等待耗时、各端资源占用、网络/collective 时间以及完整请求指标 |

TPOT 使用 benchmark 的定义；若需自行计算，明确分母是否为首 token 后的输出 token 数及少于两个输出 token 的处理。吞吐标明 input/output token、时间窗口和成功请求范围；p95 标明样本单位与算法。缺少某项时标记未采集及原因，不生成估计值冒充实测。

延迟或内存下降率 = `(baseline - candidate) / baseline * 100%`；吞吐提升率 = `(candidate - baseline) / baseline * 100%`。baseline 为零、无有效样本或测量失败时不计算百分比。用户门槛按约定的统计量判断，兼顾其精度、p95、吞吐、内存和错误率约束。

源 trace 的 kernel 累计时间、MTE2 时间和重叠机会是机制线索；目标 consumer wait/关键路径以及可比 E2E 数据才支持迁移收益。

## 交付与失败恢复

按用户交付形式提供相关文件/补丁与已有工程可执行的复现命令。代码交付不要求把分析报告加入代码 diff；迁移记录可独立保存或在回复中给出。

最小迁移记录包含：

1. H/M/HM/V/HV/MV/HMV 场景，源/目标模型、真实设备、软件/框架版本与代码 hash/commit；含版本变化时附 vLLM-Ascend/vLLM 配对、内置优化和接口映射。
2. 待迁移优化逐项决策，改动文件、契约变化、已知支持范围、回退条件和实际默认值。
3. 测试命令、运行目录/容器、各项实际结果、优化命中证据和原始数据路径。
4. T0/T1 负载/指标/统计与门槛结论；S0/S1 仅在有来源证据时附上。
5. 尚未执行的测试和阻塞项，以及失败时如何恢复本次文件、配置、包和进程。
6. 目标工作区是否已偏离源基线、本次补丁的适用范围，以及 A/B 会话的开关取值。

补丁交付自检（缺一不可）：

1. 先看目标工作区现状（`git diff -- <file>`），目标已偏离源基线时按目标结构做等价改造，不机械应用源补丁；
2. 生成只含本次增量的 focused patch（前像可用“反向移除新增块”或“HEAD + 既有改动”重建）；
3. `git apply --check` 在前像通过、应用后与部署文件逐字节一致、部署树上 `--reverse --check` 通过；
4. 共享工作区回滚只反向应用本次补丁，禁止整体 `git checkout` / `git stash` 冲掉他人改动。

重启与资源恢复见 [踩坑与排查清单](pitfalls.md) D、I 节：旧 worker 未退出会让新服务以
“显存不足”形式启动失败，清理命令的模式不能匹配到自身 shell。

部署前记录本次会替换的文件/包及 hash，优先隔离安装与编译缓存。回滚只恢复本次修改；确认文件与进程加载版本、基线/回退服务健康和必要的功能探针。恢复失败如实报告，不能只因执行了恢复命令便声称已回滚。

性能未达标时保留实验数据，将候选按用户约定置于基线/回退状态；不默认启用失败优化。没有目标硬件的交付可以标记“静态适配完成、目标验证待执行”，不可写“迁移验收通过”。
