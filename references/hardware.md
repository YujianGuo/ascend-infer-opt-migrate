# 硬件轴：A2/A3/A5 任意方向

用于 H 与 HM。支持范围是迁移分析、适配与目标验收流程；每一方向能否使用某个优化必须实证，不表示某套 kernel 自动支持所有代际。

## 环境与能力证据

在用户指定主机/容器内查询，分别保存源端和目标端记录；主机上的版本不能代替容器内版本。认证失败时停止依赖访问的动作，不能由 SSH 端口可达推断已进入容器。

| 维度 | 需要核对的证据 | 影响 |
|---|---|---|
| 设备 | `npu-smi info` 或环境已有设备查询；真实 SoC、卡数、卡健康状态、可用内存 | 编译目标、资源预算、可用并行度 |
| 软件 | 驱动/固件、CANN Toolkit/Ops、torch/torch_npu、框架/后端、编译器与自定义包版本 | API/ABI、图模式、算子分发 |
| 工程 | repo commit、工作区 diff、包加载路径、容器镜像标识、实际运行文件 hash | 防止改了另一份代码或加载旧二进制 |
| 拓扑 | 节点内/跨节点连接、HCCL、网卡/传输后端与带宽实测 | TP/EP/CP/PP、调度与 PD 开销 |
| 能力 | 当前版本文档、SDK 头文件、设备属性、API 签名和小规模实际调用 | dtype、shape、layout、workspace、同步原语支持 |

没有权限查询的字段标记未知；不采集或输出口令、密钥和令牌。文档优先使用与目标版本对应的本地资料；不足时检索官方来源，记录路径/链接、版本和约束。不要复制另一代际的参数表当作目标事实。

## 算子迁移选择

1. 先核对目标现有 torch_npu/框架算子是否语义等价、覆盖负载且可以满足需求。已有稳定实现足够时直接复用。
2. 必须保留自定义算子时核对 host tiling、设备 kernel、编译目标、注册/绑定、包加载及消费者。按目标设备重新构建；除非供应方明确保证兼容且运行验证通过，不复用源二进制或编译缓存。
3. 根据真实核数与 UB/L1/L0/workspace 预算重新检查 tile、尾块、对齐、双缓冲和跨核参与集合；核映射、布局和 flag 模式以目标文档为准。
4. 有类型、数值或 API 差异时按实际运算和 dtype 设计测试，包含受影响的极值、epsilon 可表示性、NaN/Inf 和 subnormal；不预设所有算子均需要一种统一重写。

现有 `ascendc-cross-gen-port` 与 `ascendc-cross-gen-port-light` 主要针对其入口声明的 arch22 到 arch35 方向。先检查实现、依赖和 golden 条件：前者依赖打包引擎及参考模式，后者有阶段资料和 devkit 依赖。没有这些资源或方向不符合时，使用已安装的 API、tiling、同步和精度 skills，沿目标实际工程完成迁移；不调用不存在的引擎，不倒置流程来伪装反向支持。

## 方向与两端边界

| 来源 | 目标 | 处理原则 |
|---|---|---|
| A2 | A3 | 检查实际 SoC、软件与拓扑差异，再决定复用或重构 |
| A3 | A2 | 同上，目标缺失能力用等价实现与已验证回退 |
| A2 | A5 | 核对现有跨代 skill 的实际入口范围与目标支持 |
| A3 | A5 | 同上，不以 A3 名称替代源架构识别 |
| A5 | A2 | 主动识别源实现的新能力依赖；替换目标不支持的路径 |
| A5 | A3 | 同上，重新评估资源、精度、图和通信条件 |

返回低代际时不得靠取消校验、提升容差或减少输入覆盖实现通过。目标没有所需资源或等价算法时说明不可迁移项和原因。

## 系统优化重新校准

权重预取、流水、多流、图捕获、通信计算融合、batch/chunk 和缓存预算依赖目标资源及消费者等待。源端 tile、预取字节数、并行度、capture bucket 与队列参数仅作为候选起点。

使用目标实际 TP shard/storage 核对预取范围、生命周期与依赖；确认消费者前的等待及图捕获/回放语义。kernel 时间或 MTE2 汇总下降只能支持局部机制分析，收益必须由目标端端到端对照证明。

同代服务器也记录拓扑、内存和软件差异；用户要求同代时发现代际不一致，应纠正场景并说明对实施的影响。
