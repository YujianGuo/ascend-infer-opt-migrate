# vLLM-Ascend 版本轴

用于 V、HV、MV、HMV，覆盖升级、向旧版本回迁，以及 release/rc/固定开发 commit 之间的优化迁移。适用于全部九类优化；不是不加区分地升级整套依赖或重放历史补丁。

## 固定两个版本环境

分别记录 vLLM-Ascend 与 vLLM 的 tag、完整 commit、工作区 diff；发行包记录版本、构建来源与包 hash。使用实际运行解释器确认包版本和模块加载路径，区分源码、editable 安装、wheel 和容器中残留副本。

从目标 checkout 的依赖声明、构建配置、对应版本官方发布/安装文档核对 vLLM、torch/torch_npu、CANN/Ops、编译工具链和自定义算子包配对。记录证据的版本与路径/链接；不假设 vLLM 与 vLLM-Ascend 的版本号相同就兼容，也不凭当前主分支文档为旧 release 背书。只有与被迁移功能相关的依赖需要调整。

源优化应有优化前基线与优化提交/补丁；若只提供优化后的目录，先识别改动边界，缺少基线证据时明确记录。开发分支必须固定 commit；补丁中的文件路径、参数名和环境变量只作为源码定位线索。

## 先查是否仍需移植

对照源优化改动、目标源码、相关提交和版本说明，逐项判断：

| 目标状态 | 迁移动作 |
|---|---|
| 已内置语义等价实现并覆盖所需负载 | 复用目标实现，确认分发与默认配置，验证实际命中；不要叠加重复 patch |
| 已有替代后端或实现，但契约/覆盖范围不同 | 列出差异，按目标接口适配，并保留必要回退 |
| 源优化依赖的接口被移动、删除或改变 | 沿目标调用链定位等价扩展点；不能只修 import 或复制旧类 |
| 向旧版本回迁缺少必要能力 | 使用最小等价替代；无法保持语义/验收要求时列为阻塞，不引入整套新框架来伪装支持 |
| 没有足够源码或支持证据 | 标记待验证，列出所需文件/版本资料，不编造参数映射 |

“目标已内置”仍需运行证据。目标未提供可关闭路径时，不为凑 A/B 修改内部实现；将重复移植记为无需新增，报告目标现状数据与收益无法单独归因的边界。

## 版本接口差异清单

只展开待迁移优化触及的条目；表中的接口类别是检查对象，不表示任意版本都提供某个固定名称。

| 接口类别 | 核对生产者、消费者与生命周期 |
|---|---|
| 模型与权重 | 模型注册/forward、配置、weight loader、参数映射、分片与 post-load 后处理 |
| 融合算子与分发 | Python/C++ schema、注册与 custom-op 绑定、后端选择、capability guard、fallback、编译 ABI |
| Attention 与 KV | backend/metadata 构造、packed 输入、slot/block 表、长度/position、cache spec/layout、K/V scale/offset |
| 执行与图 | worker/model runner、编译装饰器/模式、warmup、capture bucket、replay 参数/地址刷新、动态 shape |
| 并行与通信 | 进程组、rank 映射、collective 顺序、通信融合与 shard 重排 |
| 调度与 PD | scheduler/request state、token budget/chunk、抢占与回收、connector/传输协议、P/D 角色配置与元数据 |
| 配置与服务 | CLI/config/env 的名称、类型、默认值、移除/重命名、配置传递到运行时的实际消费者、服务输出契约 |

在源和目标分别搜索定义及全部调用者，生成“源入口 → 目标入口 → 契约差异 → 修改文件 → 验证”映射。先理解冲突再重实现最小差异；不能把补丁零冲突视为兼容，也不能将目标已有的校验和错误处理删掉以适配旧签名。

保持目标支持的公共接口和现有扩展点。涉及 vLLM 核心的改动时单独列出范围、配套版本和必要性，不隐藏在 vLLM-Ascend 替换包里。默认值或开关已移除时按用户需求和目标设计明确处理，不静默恢复旧行为。

## 版本迁移验收与恢复

1. 在完整、受支持的目标软件栈上先跑目标未迁移优化的基线 T0，再测同版本下仅包含迁移改动的 T1。源 S0/S1 仅解释历史收益；S1/T1 包含版本差异，不能直接归因给优化。
2. 检查真实模块/二进制加载路径与优化 dispatch，覆盖受影响的 eager、图 capture/replay、Prefill/Decode、全 ranks 和所需服务/PD 链路。只通过 import、编译、mock 或单测时，运行与收益仍未验证。
3. 按目标版本测试入口更新受影响用例/fixture；保留项目容差、失败路径和能力回退测试。启动参数可解析还需确认优化消费者实际读取并生效。
4. 软件栈需变化时隔离运行环境、编译/图缓存和自定义包；不把旧构建产物或缓存直接当作目标产物。权重或缓存格式变化只在必要时转换，记录来源、转换版本和回退副本。
5. 失败恢复到完整目标基线软件栈与配置，不仅恢复一个 Python 文件。交付源/目标配对、接口映射、最小补丁、实际测试结果、优化命中和目标 A/B 数据，缺失项标记未验证。

与硬件/模型变化组合时使用同一最终目标环境验收；有条件时拆分版本、模型和硬件的中间对照帮助归因，不强制部署所有组合。
